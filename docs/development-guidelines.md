# Development Guidelines

These guidelines support a regulated waterfall workflow.

## Planning and Scope
- Start work only after requirement and design approval.
- Ensure every code change maps to approved requirements.

## Implementation Controls
- Prefer minimal, surgical changes.
- Avoid unrelated refactors in the same change set.
- Keep documentation aligned with implementation changes.

## Review and Verification
- Perform peer review focused on correctness, traceability, and risk.
- Execute tests that demonstrate requirement fulfillment.
- Keep verification records for audits and compliance evidence.

## Change Management
- Use controlled updates with clear rationale and impact notes.
- Re-run impacted verification steps after changes.
